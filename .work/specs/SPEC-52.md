# Spec: Fix high: upgrade ws to ≥ 8.17.1
**Issue**: #52
**Date**: 2026-08-01

## Approach
The `ws` WebSocket library is a transitive dependency pulled in by `webpack-dev-server` and `socket.io` (via `karma`). The Dependabot high-severity advisory requires that no copy of `ws` in the `8.x` range below `8.17.1` is present in `package-lock.json`.

Pre-analysis shows `ws` is already resolved at `8.21.1` (well above `8.17.1`) because prior stories added a `webpack-dev-server: >=5.2.1` override that transitively resolved a newer `ws`. However, there is no explicit `ws` override in `package.json` to pin the floor and prevent a regression if the transitive resolution changes.

The remediation is to add `"ws": ">=8.17.1"` to the `overrides` section of `package.json` and re-run `npm install` to regenerate `package-lock.json` with the override formally recorded. This satisfies all acceptance criteria:
1. No `ws` 8.x below 8.17.1 in `package-lock.json` — already true, now enforced by override.
2. No high-severity `ws` advisory in `npm audit` — already clear, now permanently guarded.
3. `npm run build` passes — no source changes, override is compatible.
4. `npm test` passes — no source changes.

## Files to Change
- `package.json`: Add `"ws": ">=8.17.1"` to the existing `overrides` block.
- `package-lock.json`: Regenerated by `npm install` after `package.json` is updated.

## Files NOT to Change
- `src/**`: Out of scope — no application source changes needed.
- `angular.json`: No build configuration changes needed.
- Any other config files: Not affected by a dependency override.

## Risks / Assumptions
- `ws` `8.21.1` (the currently resolved version) is compatible with `webpack-dev-server@5.2.6` and `socket.io@4.8.3` — this is confirmed by the existing install passing build and test.
- The `>=8.17.1` range override allows npm to pick the highest compatible version and will not downgrade the currently resolved `8.21.1`.
- QA should verify that `npm ls ws` shows no version below `8.17.1` after the change.
