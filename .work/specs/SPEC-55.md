# Spec: Fix medium: upgrade esbuild to ≥ 0.25.0
**Issue**: #55
**Date**: 2026-08-01

## Approach
`esbuild` is a transitive dependency of `@angular-devkit/build-angular` / `@angular/build` and
`vite`. The current Angular 22 / `@angular-devkit/build-angular@22.1.2` toolchain already
resolves `esbuild@0.28.1`, which satisfies the ≥ 0.25.0 requirement.

To fully satisfy the acceptance criteria AND protect against any future npm-resolution
back-sliding, we add an explicit `"esbuild": ">=0.25.0"` entry to the `overrides` section of
`package.json`. This guarantees that even if a transitive requester constrains to an older
range, npm will always resolve ≥ 0.25.0.

After editing `package.json`, run `npm install` to regenerate `package-lock.json`, then
confirm with `npm ls esbuild` and `npm audit` before committing.

## Files to Change
- `package.json`: Add `"esbuild": ">=0.25.0"` to the existing `overrides` block.
- `package-lock.json`: Automatically regenerated by `npm install` to pin the new resolved version.

## Files NOT to Change
- `src/**/*`: All application source files are out of scope per the story spec.
- `angular.json`: No build system migration needed.
- Any other configuration files.

## Risks / Assumptions
- The resolved version `0.28.1` already satisfies the requirement; the override is defensive.
- esbuild has historically had breaking internal API changes between minor versions. The Angular
  CLI team manages esbuild API consumption internally, so as long as we keep the `@angular/cli`
  and `@angular-devkit/build-angular` versions unchanged, no breakage is expected.
- QA should verify `npm run build` and `npm test` both exit 0 after this change.
